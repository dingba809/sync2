# 任务列表同步状态刷新设计

## 目标

手动触发同步后，任务列表的“状态”列应从“未运行”更新为“同步中”，并在任务完成后显示“成功”或“失败”。

## 根因

服务端在任务开始和结束时会持久化 `lastStatus`，但 `TasksPage` 仅在页面首次打开以及编辑、开关等操作后加载任务数据。手动同步接口立即返回，而前端既未重新读取任务列表，也未订阅任务状态，因此表格保留了首次加载时的 `null` 值并显示“未运行”。

## 方案

1. 点击“立即同步”后调用现有运行接口，并立刻重新加载任务列表，使已写入的运行状态能反映到表格。
2. 当列表中至少有一个任务的状态为 `running` 时，以短间隔轮询现有的任务列表接口。
3. 当所有任务都不再处于 `running` 时，停止轮询；卸载页面时也清理轮询定时器。
4. 保持现有状态标签映射：`running` 为“同步中”，`success` 为“成功”，`failed` 为“失败”，空值为“未运行”。

## 测试

新增前端单元测试，覆盖：手动同步后重新拉取任务；任务处于运行中时持续刷新；任务结束后停止刷新。现有构建和类型检查必须通过。

## 范围

仅修改任务列表的数据刷新行为；不改变服务端同步逻辑、数据库结构或详情抽屉的进度订阅。
